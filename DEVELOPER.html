1. Architecture & Codebase Structure

The udi-MessanaRadiant node server is built on the Universal Devices Polyglot v3 (udi_interface) framework. It acts as an asynchronous bridge between the Universal Devices IoX event bus (eisy / Polisy) and the local Messana MCU (mBox) HTTP REST API.

2. Messana REST API Integration (v0.9.1)

The node server communicates with the local Messana Control Unit (mBox) via HTTP GET and PUT requests using an API Key. All requests include the apikey query parameter.

Transport Layer (Messana_Info.py)

  • Socket Timeouts: All requests.get and requests.put calls enforce a 10-second timeout (self.timeout = 10) to prevent hung poll threads if the controller reboots or drops connections.
  • Response Verification: Status codes are checked using resp.status_code == 200 alongside representation checks.
  • Robust JSON Property Extraction: The _extract_value() helper handles both single-key and multi-key API responses. For multi-key endpoints such as /api/zone/airQuality (which returns {"category": "Good", "value": 564, "voc": 24}), it prioritizes the numeric value property.
  • NaN Filtering: Sentinel values returned during sensor faults or communication loss (-32768 and -3276.8) are filtered to None to prevent erroneous readings.

3. Polyglot v3 & IoX Node Architecture

Every discovered Messana device is instantiated as a subclass of udi_interface.Node.

Polled Cycles & Guarded Timestamps

  • shortPoll (Default: 120s): High-priority poll for room temperatures, live status, and alarm flags. Toggles heartbeat.
  • longPoll (Default: 600s): Deep refresh of environmental sensors (VOC, CO2, air quality), setpoints, and auxiliary states.
  • Guarded TIME Driver (UOM 151): The TIME driver only updates when fresh, valid data is successfully received from the Messana API. On network dropouts or API failures, TIME remains frozen and the running state (ST or GV2) drops to 0 (Down).

Dynamic Profile Generator (profile_def.py)

The node server generates dynamic JSON profiles transmitted to IoX at startup. Depending on the TEMP_UNIT configuration parameter:

  • TEMP_UNIT = C: Assigns TEMPC (prec 1, range 5–40°C), SETTEMPC, and TEMPOFFSETC.
  • TEMP_UNIT = F: Assigns TEMPF (prec 1, range 40–104°F), SETTEMPF, and TEMPOFFSETF.
  • UDI Profile Standard Compliance: All editor IDs, nodeDef IDs, property IDs, and command IDs strictly match ^[A-Z0-9]+$ with no underscores.

Unit Conversion & Parameter Normalization (udiLib.py)

When IoX operates in Fahrenheit while the Messana system operates in Celsius, udiLib.py automatically handles bidirectional conversion:
  • convert_temp_to_messana(val): Converts setpoints from °F to °C before issuing API calls.
  • convert_rel_temp_to_messana(diff): Converts differential offsets (e.g. setback offset) without adding the 32°F zero-point bias: delta_C = delta_F * (5 / 9).
  • get_command_value(*args): Safely extracts parameter values across flat values, float strings (e.g. "21.5", "70.0"), and IoX nested query dictionaries (command['query']).

4. Automated Test Suite

The test suite contains 59 automated unit tests with zero external hardware or network dependencies.

Running the Tests

# Run using the standalone runner:
python3 run_tests.py

# Or run using Python standard unittest:
python3 -m unittest discover tests

Test Coverage Matrix

Test File Coverage Focus
tests/test_profile.py Dynamic profile generation (C/F), XML validity, uppercase ID naming conventions, version consistency across files.
tests/test_udilib.py Absolute and relative temperature conversions, UOM conversions, robust command payload extraction.
tests/test_messana_api.py HTTP transport mock tests, socket timeouts, NaN conversion, multi-key JSON parsing, subsystem alarm guards.
tests/test_nodes.py Node state transitions (ST/GV2), guarded TIME timestamps, command handlers for zones, macrozones, ATU, HCCO, and fan coils.

5. Versioning & Packaging Workflow

The node server uses unified semantic versioning. The version must remain synchronized across four locations:

  1. version.py: __version__ = "X.Y.Z" (single source of truth for runtime)
  2. version.txt: Plain text version string
  3. profile/version.txt: Profile version string
  4. server.json: "profile_version" and "version" in credits
  5. profile.zip: Archive of the profile/ folder containing the updated version.txt

The consistency test in tests/test_profile.py will fail if any of these files are out of sync.
